# Socle v0.13.2

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version laisse une boutique mesurer son audience avec Umami, sans cookie
(ADR 0034) : l'adresse du script et l'identifiant du site se règlent dans
Admin → Réglages → Mesure d'audience, et la vitrine charge alors le traceur
d'Umami. Éteinte par défaut, sans migration (deux lignes de `settings`), d'où
une version corrective. Travail d'après le pilote, hors des jalons 0 à 10
(plan §13.33).

## Ce qui change

- **Réglages → Mesure d'audience** : **Adresse du script** (https, Umami Cloud
  ou un serveur de l'agence) et **Identifiant du site**, les deux ou aucun. Le
  code de suivi d'Umami collé entier dans le premier champ est lu pour ses
  deux valeurs ; la balise elle-même n'est jamais gardée. Deux champs vides
  arrêtent la mesure. L'enregistrement purge le cache de la vitrine comme les
  autres réglages.
- **La vitrine charge le traceur**, différé, dans le `<head>` de
  `Layout.astro` (`src/features/audience/`), avec des attributs que le
  marchand ne choisit pas : chemin de la page sans paramètres ni fragment,
  sauf les paramètres de campagne `utm_*` ; navigateurs qui demandent à ne pas
  être suivis écartés ; seul l'hôte de `CANONICAL_ORIGIN` compté.
- **Ne sont jamais mesurés** : `/admin` et tout ce qui est dessous (le
  gabarit de la vitrine dessine aussi la connexion, le jeton et l'aperçu), les
  pages qui posent `Referrer-Policy: no-referrer` (`/order/<jeton>`,
  `/pay/<id>`), et un navigateur qui porte l'indice `admin_hint` : les visites
  du marchand.
- Rien ne change pour une boutique qui ne règle rien : aucun script, aucun
  en-tête de plus.

## Migrations

- aucune.

## À faire dans la boutique

- rien d'obligatoire ;
- **pour mesurer** : ajouter la boutique comme site dans Umami, recopier son
  code de suivi dans Réglages → Mesure d'audience, puis nommer Umami dans la
  politique de confidentialité, parmi les destinataires ;
- **une boutique qui avait modifié** `src/layouts/Layout.astro`,
  `src/pages/admin/settings.astro` ou `src/features/settings/db.ts` verra un
  écart à la montée : y reporter sa modification.

## Guide administrateur

- Réglages : nouvelle section « Mesure d’audience ».

## Compatibilité

Les manifestes v0.13.1 restent valides tels quels. `shopctl core upgrade` met
`coreVersion` à `0.13.2` tout seul ; une boutique qui fusionne le tag à la main
doit le faire elle-même, sans quoi la porte des manifestes refuse un manifeste
en `0.13.1` sur un socle en `0.13.2`.

La base ne bouge pas : un rollback applicatif vers v0.13.1 reste possible. Les
deux lignes `umami_*` restent alors dans `settings` sans que rien ne les lise,
et la vitrine cesse de charger le traceur.

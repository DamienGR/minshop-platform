# Socle v0.5.3

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version ajoute un raccourci d'administration sur la fiche produit
(ticket #178). Aucune migration, rien d'obligatoire dans une boutique, d'où
une version corrective. Travail d'après le pilote, hors des jalons 0 à 10.

## Ce qui change

- **« Modifier ce produit » sur la fiche produit, pour l'administrateur
  connecté seulement** (ticket #178). Un bouton fixé en bas à gauche mène à
  l'écran de modification du produit (`/admin/products/<prod_…>/edit`).
  Personne d'autre ne le voit.
  - La fiche reste partagée par le cache de l'arête : son HTML est le même
    pour tous. Le lien y est caché, sans adresse, et un script le révèle.
  - Le middleware pose un cookie `admin_hint`, lisible par le script, à
    côté d'une session qu'il vient de vérifier (mot de passe ou Access). La
    déconnexion l'efface.
  - Sans ce cookie, le script s'arrête : la page d'un acheteur n'envoie
    aucune requête de plus.
  - Avec lui, le script demande `GET /api/admin/session`, une nouvelle route
    derrière la porte de l'administration. Seul un oui montre le bouton ; un
    refus efface le cookie.
  - Le bouton est posé par la route, pas par le thème. Il vaut donc pour
    tous les thèmes, celui d'une boutique compris, aux couleurs `ink` et
    `paper` que tout thème déclare.

## Migrations

Aucune.

## À faire dans la boutique

- rien d'obligatoire ;
- **après le déploiement**, ouvrir une page de l'administration une fois
  (ou se reconnecter) : une session ouverte avant la montée ne porte pas
  encore le cookie, et le bouton n'apparaît qu'ensuite ;
- **`src/pages/products/[slug].astro`** : une boutique qui avait modifié ce
  fichier du cœur verra un écart à la montée. Garder la ligne
  `<AdminEditLink … />` et ses deux imports, sinon le bouton disparaît ;
- **la porte de sécurité distante** (`test/remote/security.mjs`) dérive les
  routes d'administration : elle vérifie d'elle-même que
  `/api/admin/session` refuse un appelant anonyme. Rien à ajouter.

## Compatibilité

Les manifestes v0.5.2 restent valides tels quels. `shopctl core upgrade` met
`coreVersion` à `0.5.3` tout seul ; une boutique qui fusionne le tag à la main
doit le faire elle-même.

La base ne bouge pas. Un rollback vers v0.5.2 retire le bouton et la route
`/api/admin/session`. Le cookie `admin_hint` resté dans un navigateur n'y sert
plus à rien et expire dans les sept jours.

# Socle v0.6.0

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version donne à l'administration un pied de page (ticket #186) et un
guide qui s'ouvre à côté de l'écran (ticket #188). Aucune migration. Version
mineure : une clé de configuration nouvelle (`admin.supportEmail`), un dossier
nouveau côté boutique (`client/guide/`) et une section nouvelle dans les notes
de version. Travail d'après le pilote, hors des jalons 0 à 10.

## Ce qui change

- **Un pied de page sur chaque écran de l'administration** (ticket #186),
  collé au bas de la fenêtre :
  - la version du socle (« Socle minshop v0.6.0 »), lue dans `package.json` ;
  - « Guide de l'administration », qui ouvre le guide sur le chapitre de
    l'écran courant ;
  - « Vous rencontrez un problème ou une difficulté ? », un e-mail prérempli
    (objet : le nom de la boutique et la version du socle) vers l'adresse que
    la boutique déclare dans `src/store.config.ts` (`admin.supportEmail`).
    Sans adresse, ou avec une valeur qui n'est pas une seule adresse, le lien
    n'apparaît pas. L'adresse se règle dans le code et non dans Réglages : le
    commerçant demande de l'aide, le code de la boutique dit qui répond.
- **Le guide de l'administration** (ticket #188) :
  - un chapitre en Markdown par écran du menu, plus « Premiers pas », dans
    `src/features/adminGuide/chapters/` (fichiers du socle), écrits pour un
    commerçant : des tâches, des étapes numérotées, les libellés de l'écran ;
  - le lien du pied de page l'ouvre dans un panneau à droite, qui pousse
    l'écran sur un grand écran et le recouvre sur un petit. Il reste ouvert
    d'un écran à l'autre, au même endroit du guide (`sessionStorage` de
    l'onglet) ; « Fermer » ou Échap le referme ;
  - sans JavaScript, le même lien mène à `/admin/guide`, le guide en pleine
    page. Le panneau charge `/admin/guide/panneau` une fois par session, et
    de nouveau quand un déploiement change un chapitre. Les deux routes sont
    derrière la porte de l'administration ; pas d'iframe, que les en-têtes de
    sécurité interdisent ;
  - les chapitres passent par `renderMarkdown()` comme une page (pas de HTML
    brut, invariant 11) ; chaque titre reçoit un identifiant `guide-…`, qui
    ne peut pas heurter ceux de l'écran ;
  - « Textes du thème » n'apparaît que si le thème déclare des textes, comme
    son entrée du menu.
- **Des chapitres propres à une boutique** : `client/guide/*.md`, fichiers de
  la boutique que le socle n'écrit jamais. Ils suivent ceux du socle, sous
  « Propre à votre boutique », dans l'ordre de leur nom (`01-accueil.md`,
  `02-…`).
- **Le guide se tient à jour par ses tests**
  (`src/features/adminGuide/guide.test.ts`) : un écran du menu sans chapitre,
  un libellé en gras qu'aucun écran n'affiche plus, un lien mort ou une
  apostrophe droite font échouer `npm test`. La typographie et les liens sont
  vérifiés aussi dans `client/guide/`.
- **Les notes de version ont une section « Guide administrateur »**
  (`scripts/release.mjs`) : dans un arbre qui porte le guide,
  `check-release` refuse une version dont la note ne dit pas ce qu'elle
  change au guide, ou qu'il est inchangé.

## Migrations

Aucune.

## À faire dans la boutique

- **l'adresse du support**, dans `src/store.config.ts` :
  `admin: { supportEmail: 'support@agence.example' },`. Sans elle, le pied de
  page n'affiche pas le lien d'aide ;
- **facultatif, un chapitre de la boutique** : `client/guide/01-<sujet>.md`,
  qui commence par un titre `## …`, pour ce que le guide du socle ne peut pas
  savoir (le thème, ses étiquettes, ses textes). Concis, direct, pour une
  personne non technique ;
- **`src/layouts/AdminLayout.astro`** : une boutique qui avait modifié ce
  fichier du cœur verra un écart à la montée. Garder le pied de page, la ligne
  `<GuidePanel … />` et le script en ligne de l'en-tête, sinon le guide ne
  s'ouvre plus à côté de l'écran.

## Guide administrateur

- nouveau : les douze chapitres du socle (Premiers pas, Tableau de bord,
  Produits, Commandes, Clients, Catégories, Pages, Navigation, Livraison,
  Médias, Textes du thème, Réglages).

## Compatibilité

Les manifestes v0.5.x restent valides tels quels. `shopctl core upgrade` met
`coreVersion` à `0.6.0` tout seul ; une boutique qui fusionne le tag à la main
doit le faire elle-même.

La base ne bouge pas. Un rollback applicatif vers v0.5.3 retire le pied de
page et le guide. Un retour du code à v0.5.3 doit aussi retirer la clé
`admin` de `src/store.config.ts`, que l'ancien socle ne connaît pas.

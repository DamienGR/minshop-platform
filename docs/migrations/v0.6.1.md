# Socle v0.6.1

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version met une photo à côté de son texte dans une page (ticket #195),
laisse `shopctl deploy` lire l'adresse du support sur GitHub depuis un poste,
et donne plus de temps à un test qui bâtit un socle. Aucune migration, rien
d'obligatoire dans une boutique, d'où une version corrective. Travail d'après
le pilote, hors des jalons 0 à 10.

## Ce qui change

- **Une photo à gauche ou à droite de son texte, dans une page** (ticket
  #195, PR #197). Le titre d'une image Markdown, un mot parmi deux :
  `![Mes mains à l’atelier](/images/… "gauche")` ou `"droite"`.
  - À partir de 640 px de large, la photo se place de ce côté, sur 40 % de
    la largeur du texte, et les paragraphes qui suivent s'écrivent à côté,
    puis dessous. Un intertitre, un filet, une carte ou une autre photo
    repartent sous la photo. Sur téléphone, la photo reste au-dessus du
    texte.
  - Le mot n'arrive jamais sur la page : le rendu en tire une classe d'une
    liste fermée (`markdown-media--left`, `--right`), et ne l'écrit pas dans
    `title` (pas d'infobulle « gauche »). Tout paragraphe qui ne tient
    qu'une image prend aussi la classe `markdown-media`. Un autre titre
    reste un titre ; dans une phrase, une liste, une citation ou une rangée
    de photos, le mot ne déplace rien.
  - Dans l'éditeur de page, **À gauche** et **À droite**, après **Image**,
    écrivent le mot sur l'image de la ligne du curseur ; un second clic
    remet la photo en pleine largeur. L'aperçu montre le résultat.
- **`shopctl deploy` lit `MINSHOP_SUPPORT_EMAIL` sur GitHub quand le shell
  ne l'a pas** (PR #193) : la variable du dépôt de la boutique, puis celle
  de l'organisation partagée avec lui, par `gh` et le scope `repo`. Jamais
  dans un workflow, jamais bloquant : sans `gh` ou sans session, le
  déploiement avertit et dit où il a cherché. Le rapport dit d'où vient
  l'adresse (`supportEmailFrom`).
- **`test/scripts/core-repository.test.mjs`** prend le délai de 60 secondes
  de ses voisins (PR #192) : bâti depuis une boutique, le socle de test
  dépassait les cinq secondes de vitest.
- **Porte navigateur** : les specs de l'administration partagent une
  connexion par worker (`signIn()`, `test/browser/admin.mjs`), sous la limite
  de dix connexions par minute ; une page aux photos de côté est semée par
  `serve.mjs` et parcourue par axe et le contrôle de débordement.

## Migrations

Aucune.

## À faire dans la boutique

- rien d'obligatoire ;
- **un thème qui cadrait lui-même les photos d'une page** (par exemple
  `p:has(> img)` dans `src/themes/<thème>/tokens.css`) : vérifier sa page
  après la montée. Le socle pose maintenant `markdown-media` sur un
  paragraphe qui ne tient qu'une image, et `clear: both` sur les intertitres,
  les filets, les cartes et ces paragraphes ; une règle du thème sur la même
  photo peut se cumuler avec. Pour mettre une photo à côté de son texte,
  l'éditeur suffit ;
- **le déploiement depuis un poste** : `gh auth login` sur ce poste suffit
  pour que l'adresse du support vienne de GitHub ; un `export
  MINSHOP_SUPPORT_EMAIL=…` du shell garde la priorité.

## Guide administrateur

- Pages : nouvelle section « Mettre une photo à côté du texte ».

## Compatibilité

Les manifestes v0.6.0 restent valides tels quels. `shopctl core upgrade` met
`coreVersion` à `0.6.1` tout seul ; une boutique qui fusionne le tag à la main
doit le faire elle-même.

La base ne bouge pas. Un rollback vers v0.6.0 remet les photos en pleine
largeur, au-dessus de leur texte ; le mot `"gauche"` ou `"droite"` redevient
le titre de l'image (une infobulle), sans rien casser.
